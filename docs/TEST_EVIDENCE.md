## Limits

These are Chromium desktop automation results. They do not establish physical phone keyboard behavior, mobile GPU performance, mobile app compatibility, Chromebook behavior, portal compatibility, network performance, accessibility certification, moderation completeness, public population quality, player enjoyment or visual acceptance. Those outcomes remain explicitly unverified. Chat restrictions remove the extra channel for revealing clues during a case; they cannot prevent coordination outside the game.

SDK gates use a fake SDK response with the production loader and application. The standard build selects the local adapter. A separate loopback preview selects the SDK guest flow. Profile display, verified platform account handling when applicable and final chat behavior must be completed for the QA selected platform route. Passing these fixtures is not a portal integration pass.

A previous revision separately reached the local environment using the actual external SDK. Its temporary observation file was removed by subsequent browser runs, so it is not evidence for this candidate or counted among deterministic tests. The current SDK fixtures do not verify the CrazyGames portal or mobile app.

The development server listens on 0.0.0.0 on port 3000 for phone testing, now also the CLI default. A request from the computer to http://192.168.1.11:3000/health returned ok. A later mobile browser emulation on this address reproduced the missing randomUUID error before the fix, then successfully created and joined the same room after it. A duplicate desktop listener was subsequently reproduced as the cause of separate room lists and stopped; room joining between the two addresses then succeeded in both directions. These observations do not establish connectivity from a physical phone through the WiFi network or Windows firewall.
